# Release Checklist Sprint

Run a focused release sprint on your capstone. Choose the highest-risk pages first. Do not wait for the site to feel perfect before testing.

## Validate at least two representative HTML pages and your main CSS file.
- All HTML pages and the CSS file pass the W3C checker

## Check all primary navigation links and at least five content/action links.
- Nav is entirely functional, form submit button is functional, all links to external pages are functional

## Test one representative page at narrow, medium, wide, and 200% zoom.
- Home page is responsive, all items are visible and usable at narrow, medium, and wide viewports
    - Inspected via Chrome DevTools
- 200% zoom functionality is present as well

## Test keyboard navigation and visible focus on the header, main content links, and any form/control.
- Focus-visible and keyboard navigation is functional and accessible, form functionality is present

## Run one performance diagnostic and identify the top issue you can realistically improve or document.
- Lighthouse diagnostic on coaches.html page mentions images could use improved compression
    - Images will be replaced with smaller image/WEBP files
    

## Check metadata on the published or preview URL if available.
- Metadata checked through the Rich Results Test (https://search.google.com/test/rich-results) and Schema.org validator (https://validator.schema.org/)

## Fix at least three issues or document why a remaining issue is outside final-week scope.
- Placeholder images and text will be replaced 
- Hero image reduced in size and converted to WEBP
- Remaining issue:
    - Images were to be added at bottom of home page, would require restyling, sourcing, crediting, and redoing media inventory.
